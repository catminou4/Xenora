## [Unreleased]

### Added

- Added the gfx1030 semantic campaign roadmap and ledger (#526, #527). It records the starting coverage, family and operand gaps, current owners, and the evidence required for each implementation batch.
- A bounded standard input for hosted C programs (#467, package 1c of #459): `xenora run` reads its own standard input before the run starts, up to 1 MiB, and the guest's `stdin` serves it through `fgets`, `getchar` and `feof` with text-mode replacement of CR LF by one line feed. Input beyond the limit is refused with a command-line error before anything executes, never truncated silently; no input at all - a terminal, or the diagnostic channel holding fd 0 - means end of file at once, so a run stays deterministic. The end-of-file indicator follows ISO C: it is set when a read meets the end, so a last line without a newline sets it while a line feed does not. A line longer than the buffer comes in pieces of count - 1 characters without loss, and a CR alone is not translated. `scanf`, wide input and interactive input remain out of scope, as the ticket says. One test in `runtime_services.rs` covers the edges; a hosted mingw-w64 program, `crt_stdin.c`, passes all its checks through `xenora run` at `-O0` and `-O2` with the fixed input piped in and with none, its control variant exits non-zero, and a run fed 1 MiB + 1 byte is refused before the program starts. Locally tested on Apple Silicon only; not compared with Windows and not independently reviewed.


Guest execution uses original, purpose-built test programs. Commercial Xbox game execution
remains unsupported.

### Added
- Added partial `CreateSemaphoreExA/W` support for unnamed guest semaphores (#512). The requested access mask controls wait and release operations. Kernel32 and the documented API-set aliases resolve to the same services. An original guest fixture exercises both entry points at four optimization levels.
- File positions and file operations for C programs (#493, first part of package 4 of #459): `_ftelli64`, `_fseeki64`, `fgetpos` and `fsetpos` on streams `fopen` returned, and `remove` and `rename` through `api-ms-win-crt-filesystem-l1-1-0.dll`. A program that imported any of them was refused before its entry point. A position is the byte offset on Xenora's in-memory drive, so a line feed written in text mode counts two; seeks before the start, unknown origins and null arguments fail with `EINVAL`, and positions of the standard streams stop the guest. `fseek`, `ftell` and `rewind` stay with #312. One test in `runtime_services.rs` covers each origin, the round trip through `fpos_t`, writes past the end, and the `errno` of each failure; a hosted mingw-w64 program, `crt_files.c`, passes all 28 of its checks through `xenora run` at `-O0` and `-O2`, and its control variant fails as intended. Locally tested on Apple Silicon only; not compared with Windows and not independently reviewed.
- The buffer forms of the C runtime `printf` family (#466, package 1b of #459): `__stdio_common_vsprintf`, `__stdio_common_vsprintf_s`, `__stdio_common_vfprintf_s` and `putchar`, so a hosted program can format into its own memory with `snprintf`, `sprintf`, `_snprintf` or `sprintf_s` instead of being stopped at the first call. The return value and termination rules of the standard and legacy forms come from Microsoft's `snprintf` and `_snprintf` pages, and the secure form's empty-the-buffer error reporting from `sprintf_s`; which rules apply is selected by the option bits, matching the constants observed in the code mingw-w64 generates (`0x1` legacy, `0x2` standard, verified by disassembly). Writes never leave the stated buffer, a fault inside it stops the guest, and a truncated legacy write leaves `errno` alone. An exact fit in the legacy form writes the text without a terminator and returns its length. A null buffer with zero capacity queries the required length in both forms. The invalid parameter handler is not modelled, so callers receive the documented result for continued execution. The one-line `__stdio_common_vsprintf` stub in `static_cxx.rs` is removed, as the ticket discussed, because the typed registry now serves the real entry point. The runtime tests cover exact fits, one-byte-short truncation, zero sizes, null buffers, guard bytes and faults. A hosted mingw-w64 program, `crt_sprintf.c`, checks the same behavior through `xenora run` at `-O0` and `-O2`, with a control variant that expects an incorrect result. Locally tested on Apple Silicon only; not compared with Windows and not independently reviewed.
- Temporary files for C programs (#493, last part of package 4 of #459): `tmpfile` and `tmpnam` through `api-ms-win-crt-stdio-l1-1-0.dll`. A program that imported either was refused before its entry point. `tmpfile` opens a binary stream for reading and writing whose file is deleted when the stream closes; `tmpnam` writes a name no file on the drive holds, into the caller's buffer or a static one when the argument is null. One test in `runtime_services.rs` covers the names' uniqueness against the drive, the single static buffer, and the deletion on close; a hosted mingw-w64 program, `crt_tmp.c`, passes all 9 of its checks through `xenora run` at `-O0` and `-O2`, and its control variant fails as intended. Locally tested on Apple Silicon only; not compared with Windows and not independently reviewed.
- The remaining 49 common `math.h` functions of the Universal C runtime, through `api-ms-win-crt-math-l1-1-0.dll` (#468, package 3 of #459): `acos asin atan atan2 cbrt ceil copysign cos cosh erf exp exp2 expm1 fdim floor fmax fmin fmod frexp hypot llround log log10 log1p log2 lround modf nearbyint pow remainder rint round sin sinh tan tanh tgamma trunc` and `atan2f ceilf cosf expf floorf fmodf logf powf roundf sinf tanf`. A program that called any of them was refused before its entry point. They are typed registry services in the new `crates/loader/src/services/crt_math.rs`, with arguments and results in XMM registers. Functions whose result IEC 60559 fixes exactly (rounding to an integer, `copysign`, `fmod`, `remainder`, `fmax`, `fmin`, `fdim`, `frexp`, `modf`, `lround`, `llround`) are computed on exact operations; the others return the macOS host math library's result, which the registry says can differ from the UCRT's in the last place (macOS `atan2f(-0, -0)` is already one ulp inside -pi). `errno` is never set, no exception flag is raised and `rint`/`nearbyint` always round to nearest; a NaN argument comes back quieted and a domain error gives the x86 default NaN. `frexp` and `modf` stop the guest with a memory fault on an unwritable pointer. Five tests in `runtime_services.rs` cover Annex F special values, hand-derived exact results at ties and integer-range edges, and 1-ulp agreement with references computed independently with mpmath (`tests/compat_fixtures/crt_math_reference.py`). A hosted mingw-w64 C program, `crt_math.c`, passes all 110 of its checks through `xenora run` at `-O0` and `-O2`, and its control variant fails as intended. Locally tested on Apple Silicon only; not compared with Windows and not independently reviewed.
- Partial kernel32 services `TerminateProcess`, `GetExitCodeProcess`, `GetCurrentThreadStackLimits`, `GetThreadGroupAffinity` and `SetThreadGroupAffinity` (#475). `TerminateProcess` ends only the modelled guest process, through the current-process pseudo-handle, and fails with `ERROR_INVALID_HANDLE` for any other handle; no host process is touched. Stack limits come from the calling guest thread's TEB. Affinity reports one group holding every processor the guest is shown; narrower masks are refused with `ERROR_NOT_SUPPORTED`. An original C fixture built at `-O0`, `-O1`, `-O2` and `-Os` exercises them under the guest thread scheduler. Locally tested only; not independently reviewed.

### Changed

- Native CI runs the QA and release-tooling tests and checks both agent shell launchers for syntax errors (#545).
- The native fixture viewer reuses its frame readback buffer and republishes the image only when the fixture frame ID changes. Paused loops use a 250 ms polling interval, and Pause, Resume and Stop refresh native status immediately (#405).
- The decoder accepts `LOCK` on the memory-destination forms of ADD, OR, ADC, SBB, AND, SUB and XOR, as Intel SDM Vol. 2 lists them, not only on XADD and CMPXCHG (#447). libstdc++ uses `lock add` and `lock sub` for reference counts. `LOCK` on CMP, on a register destination and on XCHG is still refused. Locked instructions now always run on the shared semantics rather than native ARM64 code, so atomicity has one place to live once guest threads run concurrently; today they run one at a time, so a locked read-modify-write is already indivisible.
- Static probe exports now check every destination before writing, preserve the ignored development directories and publish complete files by rename. Future persistent caches use a separate per-user location outside Git checkouts (#413).
- TLS setup now copies templates from 64 KiB up to 1 MiB straight into the zeroed thread data block, after checking that every template byte is readable, instead of staging them in a second buffer (#111). The pointer array and data block layout, the TLS index write and the error for an unreadable template are unchanged, and nothing is mapped when the template cannot be read. On an Apple M2 Pro, median setup time for original synthetic templates over 31 interleaved samples fell by 21.7 % at 64 KiB, 19.0 % at 256 KiB and 14.2 % at 768 KiB. Smaller and larger templates keep the single staged read and showed no change beyond run-to-run variation.
- Guest `strlen`, `strnlen`, `wcslen` and `wcsnlen` scan memory in 256-unit blocks, falling back to single units at mapping boundaries so faults still report the first inaccessible unit. On Apple M2 Pro the 63-byte `strlen` workload went from 1,990 ns to 223 ns per call (median of 10 batches, on a machine that was not idle).
- The native ARM64 DBT now runs the 32- and 64-bit register and immediate forms of ADC and SBB itself instead of falling back to the shared interpreter (#195). The guest CF is moved into the host carry before ADCS or SBCS, inverted for SBB because SBCS subtracts NOT C while SBB subtracts CF. Memory forms and 8- and 16-bit forms still use the shared semantics. `tests/x86_carry_chain.rs` runs 256-bit add and subtract chains of 64- and 32-bit limbs, in one block and split one block per limb, against widening `u128`/`i128` reference arithmetic in both engines, plus immediate 128-bit increments and decrements and the `sbb reg, reg` carry mask. Locally verified on Apple M5 only.
- Removed the temporary region-list allocation from each instruction-byte fetch while preserving lookup order, execute-permission checks and error behavior (part of #104).
- Release and bench builds now use fat link-time optimization with one codegen unit (#116). On a local Apple M5, `dbt_bench` medians over five alternating runs dropped by about 6 % for the interpreter (903 to 845 µs) and about 9 % for cold DBT (1.155 to 1.046 ms), while warm DBT (cache hits) became about 2 % slower (21.83-22.08 to 22.29-22.54 µs over four further runs). The `xenora` binary shrank from 2.73 to 2.11 MB. A clean release build of the workspace takes about 14 s instead of 6 s. Debug and test builds are unchanged.
- The ARM64 assembler loads 64-bit constants with the fewest MOVZ or MOVN plus MOVK instructions (#92). It no longer emits MOVK for zero halfwords and starts from MOVN when more halfwords are 0xFFFF than zero, so small negative values take one instruction instead of four. On Apple M5 the DBT benchmark emits 245,168 instead of 290,184 native bytes for its 626 blocks (-15.5%) and the 1,048 integer fixture instructions 128,724 instead of 145,732 (-11.7%); benchmark run times did not change measurably. New tests check the sequences against LLVM encodings and execute 1,056 of them on the host through the JIT.
- Resolve the tiled BC1 mip and array layer once per linearization and copy contiguous block runs within each tile row. Partial edge blocks are retained and padding slots are skipped. Closes #349.
- Added module identity for guest programs (#487): `GetModuleHandleA/W` return the program's base address for a null name, and `GetModuleHandleExA/W`, `K32GetModuleInformation` and `GetModuleInformation` are implemented, with counted references, pinning and lookup by address. `GetProcAddress` now finds services registered after the module catalog, such as `ExitProcess`, and KernelBase is a module of its own. `GetModuleHandle`, `GetProcAddress`, `FreeLibrary` and `LoadLibrary` resolve through the API sets Microsoft lists. Original C and C++ programs built by the tests exercise them; nothing was compared with Windows, and independent review is pending.
- Changed the default report folder of `xenora probe` and `xenora imports sync` to `diagnostics/probe`, which Git ignores (#364). Anyone relying on the earlier default has to pass `--report`.
- Relocation reports now build their type histogram once per image, avoiding a tree lookup for every entry. Target checks and fixup order are unchanged; synthetic regressions and an opt-in relocation timing test cover the change (#109).
- Moved the six supported gfx1030 SOPP compute control forms into the semantic registry, preserving instruction decoding and shader lowering. Part of #215.
- Moved gfx1030 `s_mov_b32` (SOP1) into the semantic registry, preserving its existing decode domain and shader output. The move operand rule retains explicit VCC and EXEC half destinations. Part of #215.
- Moved the six hand-written gfx1030 VOP2 logical and shift forms (`v_and_b32`, `v_or_b32`, `v_xor_b32`, `v_lshlrev_b32`, `v_lshrrev_b32`, `v_ashrrev_i32`, AMD guide section 12.7) into the semantic registry under a new VGPR-only operand rule `vop2_vgpr2`, with no behaviour change: a sweep of 132,608 VOP2, VOP1 and SOP1 words decodes to the same text, length and error before and after, the MSL goldens are unchanged, and the runtime-region allowlist admits exactly the same six forms. The per-lane `VectorBinary` gained `And`, `Or`, `Xor` and the three shifts (count masked to S0[4:0]); 6 hand-written instruction variants and their decoder and lowering arms are gone (17 hand-written forms remain). Part of #215.
- Added non-blocking Metal compute submission through `submit_words` and `wait`, with completion-aware resource retirement and a sixteen-dispatch in-flight limit. Synchronous calls keep their existing behavior. The benchmark reports the host submission split and compares synchronous and pipelined batches.
- Native Metal compute submissions now recycle completed input/output shared buffers through a bounded exact-size pool instead of allocating two buffers per dispatch. Every checkout recopies the input and restores the output poison, and buffers return to the pool only after a terminal Metal command status. On Apple M1, a 31-sample release benchmark reduced median allocation time by 69.9-98.7% across 25 fixture/size combinations; host timings were noisy on battery power, so no end-to-end speedup is claimed (#134).
- Reuse up to 16 native Metal compute pipelines per context for repeated shader source and entry points. Pending dispatches retain their pipelines through completion, including after eviction. Dispatch profiles report zero library and pipeline setup time when a cached pipeline is reused. Closes #132.
- Avoided resolver allocations for permitted guest data reads and writes contained in one mapping, preserving checked fallback for split spans and faults (#105).
- Extended the read-only RDNA2 planning CLI (`python3 -m qa rdna2`) with family/status filters, compact summaries, Codex-ready manifests under `artifacts/`, active-claim exclusion (family claims exclude those families; path-only claims block overlapping permitted files), coverage reconcile against `semantic_coverage` without inflating counts, and inventory diffs. Covered by `tests/qa/test_rdna2_plan.py`; planning only, no GPU production edits.

### Fixed
- The PE loader ignores thread-local storage directory bytes outside the optional header's declared directory count, so padding is not treated as TLS metadata (#573).
- Structured startup reports now preserve the guest exit status when a thread-local storage callback ends the process before the entry point. The report keeps TLS as the last completed stage (#483).
- `xenora run --startup-report` preserves piped guest input and applies the usual input size and deadline limits (#547).
- The macOS fixture loop now displays failed session commands with their status codes even when a frame is on screen. Both fixture modes share session replacement and cleanup, and a cancelled poll cannot touch a replacement session (#406).
- Hosted program arguments now also respect the 32,767-unit Windows UTF-16 command-line limit after quoting, including the terminator. A rejected replacement leaves the current arguments intact (#581).
- The DBT no longer runs a stale translation after the guest rewrites its own code or runs against a different address space (#84). Each cached block now keeps the guest bytes it was translated from and is compared with the current executable bytes on every lookup; a mismatch, or bytes that are no longer readable, discards the block and translates it again, counted in the new `DbtMetrics::blocks_invalidated`. This makes the `cpu_known_answers` self-modifying-code case pass for the DBT, so it is no longer ignored as a known defect, and regression tests cover a rewritten block, a rewritten final byte, a budget-limited block and a second address space. The discarded native code stays in the JIT cache until cache reclamation exists (#99), and a store into a block's own later instructions during the same dispatch is not detected. Local verification only; not independently reviewed.
- `xenora inspect` reports filesystem errors separately from invalid PE headers and refuses special files such as FIFOs. Symlinks to regular files still work (#557).
- An instruction longer than 15 bytes now stops both engines with a general-protection fault instead of an illegal-instruction exit (#384; Intel SDM Vol. 3A, 7.15). The decoder still stops before fetching a 16th byte, and the DBT translates the faulting instruction on its own so the instructions before it in a block complete first. The `defect_overlong_instruction` known answer from #155 is now verified, with three more cases.
- The graphics shader compiler rejects image-sample coordinate and result spans that cross the VGPR limit (#569).
- Fixed the app's executable inspector so a late result from an earlier selection can no longer replace a newer one (#407). Each selection from the file picker, drag and drop or Finder Open With now takes a request number, and only the latest request may publish its report and status or clear the busy state. The previous report is cleared when a new file is chosen, and a failed inspection of the latest file is shown in red above its report. The read itself is unchanged: size checked before reading, balanced security-scoped access, nothing executed. `Xenora --smoke-inspection-order`, run by `scripts/build-app.sh`, drives the model with an injected slow and fast reader and checks a stale success, a stale failure and a busy state held for the newer request; all four checks fail without the change. Checked locally on Apple Silicon; not yet independently reviewed.
- The relocation stage rejects nonpreferred placement for fixed-base PE images. The original delay-import fixture now provides the three fixups needed by the bundled worker smoke test (#570).
- Non-canonical 64-bit guest data addresses now raise `#GP` instead of a memory fault in both the interpreter and native DBT, including accesses that cross the canonical-address boundary. The synthetic architectural test is enabled again.
- Agent sync reports upstream changes on both the old and new paths of a rename (#558).
- Made the native semantic-review timeout in `scripts/test-gpu.sh` configurable with `XENORA_SEMANTIC_TIMEOUT` and raised its default from 120 to 300 seconds, so cold Apple Silicon runs do not fail while the expanded Metal known-answer suite is still progressing.
- The CPU depth reference rejects clears outside the finite viewport depth range and caps targets at 4,096 pixels before allocation (#550).
- Added a Python 3 fallback for `timeout` in `scripts/test-gpu.sh`, so the native Metal suite runs on stock macOS without GNU coreutils while preserving bounded execution and the usual timeout exit status.
- RDNA2 fixture regeneration builds the entire batch before updating checked-in binaries. An assembly or extraction failure leaves existing binaries intact (#597).

### Added
- Guest CPU faults become structured exceptions, and `__C_specific_handler` is implemented (#453). A divide error, an access violation and UD2 in guest code now start the same search as `RaiseException`, as `STATUS_INTEGER_DIVIDE_BY_ZERO`, `STATUS_ACCESS_VIOLATION` (read, write or instruction fetch, and the address) and `STATUS_ILLEGAL_INSTRUCTION`. Other faults, including any other refused opcode, the runtime-limit marker, general-protection and SIMD faults and faults inside host services, still stop the guest, and a fault nothing accepts stops it with the original reason at the faulting instruction. `__C_specific_handler` runs MSVC-style C `__try`/`__except`/`__finally` scope tables, whose layout was derived from original clang `-fasync-exceptions` and mingw-w64 programs because no public page describes it. Exception handlers now get the context of the raise or fault, and continuing execution applies their edits to it. An uncaught C++ exception in a mingw-w64 program no longer stops at a stub: the C runtime's startup filter lets `std::terminate` print the exception and `abort` exit with status 3. `crates/loader/tests/guest_c_seh.rs` runs ten cases of the original `tests/compat_fixtures/guest_c_seh.c` at `-O0`, `-O1` and `-O2` against expectations written from the source. Verified locally on Apple Silicon; not independently reviewed. Nothing was compared with Windows or Xbox hardware. The unhandled-exception filter is still not called.
- The README now takes contributors from a native toolchain check through building Xenora.app and rendering its first synthetic frame. `scripts/build-app.sh --check` reports the selected Apple Silicon prerequisites before a build (#403).
- `xenora run --startup-report` now returns a versioned startup summary with the last completed stage, the original failure context, and a distinct timeout or unknown worker termination outcome. The supervisor retains valid events even if a worker leaves a damaged or incomplete record (#411).
- Existing RGBA8 Metal textures can now update selected mip levels through one bounded staging buffer. A batch validates every supplied level before writing, coalesces compatible row copies into the same command buffer, and waits for completion. Omitted levels keep their contents (#145).
- C++ exceptions run in guest programs (#447). A statically linked mingw-w64 C++ program (`-static-libstdc++ -static-libgcc`) carries GCC's unwinder and C++ personality as guest code; the guest runtime now provides the operating-system side they call. Startup reads and checks the image's exception directory (data directory 3) and refuses a malformed one. `RtlLookupFunctionEntry`, `RtlVirtualUnwind` and `RtlCaptureContext` work on the x64 `RUNTIME_FUNCTION`, `UNWIND_INFO` and `CONTEXT` layouts, including prologs, the listed epilog forms, frame registers, saved XMM registers, large allocations, machine frames and chained entries; unknown unwind versions and operations stop the guest with the new `ExitReason::InvalidUnwind` rather than being guessed. `RaiseException` runs a search phase and `RtlUnwindEx` an unwind phase that call the guest's language handlers with an `EXCEPTION_RECORD`, `CONTEXT` and `DISPATCHER_CONTEXT` on the guest stack, follow a handler that raises or unwinds again, run termination handlers in the frames passed and install the target context. Layouts were checked with `offsetof` against the mingw-w64 14.0.0 headers. Not modelled: exit unwinds, collided-unwind and nested-exception dispositions, handler edits to the context on continue-execution, `KNONVOLATILE_CONTEXT_POINTERS`, the unhandled-exception filter, CPU faults as exceptions and `__C_specific_handler`, which is still a stub; an exception nobody catches reaches the C runtime's startup frame and stops at that stub. The original program `tests/compat_fixtures/guest_cpp_exceptions.cpp` throws an `int`, a `std::runtime_error` through five frames whose destructors run, a rethrown `std::logic_error`, a class caught by `catch (...)`, a nested throw from a handler, and an exception through a frame with an 8 KiB allocation while floating-point values live in callee-saved XMM registers. `crates/loader/tests/guest_cpp_exceptions.rs` runs it at `-O0`, `-O1`, `-O2` and `-Os` through the loader and the ARM64 DBT against output written from the source, plus the uncaught control. Verified locally on Apple Silicon; not independently reviewed. Nothing was compared with Windows or Xbox hardware.
- Added the remaining imports of a statically linked mingw-w64 C++ program (#447): `libwinpthread-1.dll`'s `pthread_once`, key and mutex functions, which GCC's emulated thread-local storage calls, with the host keeping lock and key state because guest threads never run concurrently (key destructors are never called; mutex attributes are refused); `memchr`, `strchr` and `getenv`, which finds nothing because the environment is empty; `LocalFree` of a null handle; and `FormatMessageA`, `rand_s`, `_read` and `__stdio_common_vsprintf` as stubs that stop the guest if called.
- The guest graphics command context can create a bounded timeline fence, signal it after completed draw work, place a wait before the next command on the same or another queue, and read or wait for its completed value (#296). The native adapter uses a Metal shared event and separate signal and wait queues. The deterministic software path applies the same ordering contract. Waits are bounded, and a submission whose producer has yet to signal can be retried. Decreasing signals and Xbox-specific fences are unsupported. The draw/readback path remains synchronous, and fence calls are not yet guest imports. The contract follows Microsoft's [queue signal](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12commandqueue-signal), [queue wait](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12commandqueue-wait) and [completed value](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12fence-getcompletedvalue) documentation and Apple's [shared events](https://developer.apple.com/documentation/metal/mtlsharedevent).
- The native app can run any executable (#442). Its new Run action sends the inspected file and any typed program arguments to the bundled `xenora run` worker from #439, so a run from the app keeps the worker's separate process, wall deadline and step limit. The app shows the program's standard output and standard error, its exit status and the last startup stage. A View > Show Metal HUD switch, off by default and remembered between launches, overlays the Metal device, frame size, frame counters and host-measured timings on fixture frames, and turns on stage tracing for program runs, which have no draw path yet. `scripts/build-app.sh` bundles and checks the worker, and its new `--smoke-hud` and `--smoke-run-program` checks need no GPU. Checked locally on Apple M4 in the running app: the Gate A2 program ran with arguments to exit 0 with all 76 checks passed, and the HUD showed and hid on a fixture frame and the frame loop. Not independently reviewed.
- Added `docs/research/exception-handling.md` (#441). It maps the public Windows x64 exception and unwind ABI (`.pdata`, `UNWIND_INFO`, unwind codes, two-phase dispatch, `EXCEPTION_RECORD` and the six services) to the pieces Xenora's guest runtime lacks. It also records what two original probe programs do on current main. A C `__try`/`__except` around a divide by zero stops the guest with `DivideError` instead of reaching its handler. A statically linked mingw-w64 C++ program that throws is refused before entry, and its exception-specific gaps are `RaiseException`, `RtlCaptureContext`, `RtlLookupFunctionEntry`, `RtlUnwindEx` and `RtlVirtualUnwind`, plus the `__C_specific_handler` stub. The page lists unknowns and source inconsistencies, a fixture plan and ranked follow-ups. Research only; no behaviour changed.
- Added the C++ runtime services a mingw-w64 C++ guest imports (#437). `libstdc++-6.dll` now provides `operator new` and `operator delete`, which reuse the same guest heap the C runtime's `malloc` and `free` use, `std::string`'s out-of-line `_M_dispose` and `_S_copy`, and libstdc++'s length-error, bad-allocation, logic-error, bad-array-length and assertion paths. The last four are noreturn functions, so they stop the guest with the runtime-limit fault instead of returning, which is an explicit refusal rather than a silent no-op. `libgcc_s_seh-1.dll!__emutls_get_address` is provided as well: GCC's emulated thread-local storage passes the address of a descriptor holding one variable's size and alignment, and the runtime returns the calling thread's own block for it, so two guest threads never share a thread-local variable. The layout is the one the toolchain's own `bits/basic_string.h` documents.
- Added `run_synthetic_startup_scheduled` to the loader (#437). The startup path ran the entry point directly, so a guest that called `CreateThread` was refused with `ERROR_NOT_SUPPORTED` because no scheduler was attached. The new entry point runs the same startup under the deterministic cooperative scheduler, so the entry point and the threads it creates take turns and share one instruction budget. A guest that exits the process still reports its own exit status.
- Added the SSSE3 instructions on XMM registers, and the 0F 38 and 0F 3A opcode maps they need, to the instruction registry (first part of #481): PSHUFB, PHADDW, PHADDD, PHADDSW, PHSUBW, PHSUBD, PHSUBSW, PMADDUBSW, PSIGNB, PSIGNW, PSIGND, PMULHRSW, PABSB, PABSW, PABSD and PALIGNR. Both engines run them on the shared semantics; none is lowered to NEON yet. The MMX forms stay refused, so CPUID does not report SSSE3. Seven SDM-derived cases already in `cpu_known_answers.rs` moved from refused to verified, with 72 LLVM-assembled fixtures; not compared with x86 hardware and awaiting independent review.
- Added the integer SSE4.1 instructions on XMM registers to the instruction registry (second part of #481): PMOVSX and PMOVZX in all six widths, PMINSB, PMINSD, PMINUW, PMINUD, PMAXSB, PMAXSD, PMAXUW, PMAXUD, PMULLD, PMULDQ, PCMPEQQ, PACKUSDW, PBLENDVB, PBLENDW, PTEST, PHMINPOSUW, MPSADBW, MOVNTDQA, PEXTRB, PEXTRW to memory, PEXTRD, PEXTRQ, PINSRB, PINSRD and PINSRQ. Both engines run them on the shared semantics. Ten SDM-derived cases already in `cpu_known_answers.rs` moved from refused to verified, with 254 LLVM-assembled fixtures; not compared with x86 hardware and awaiting independent review.

### Fixed

- Fixed the intermittent failure of the frame-loop memory-footprint test (#290). Each frame-loop session opened its own Metal command queue. The first command buffer on a queue makes the GPU driver allocate a working set for it (about 45 MiB on an Apple M5 with Metal validation), and the driver frees it asynchronously 10–50 ms after the queue is released, so the process footprint read right after a session ended depended on how far that release had got.
